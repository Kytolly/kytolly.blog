DiffTaichi：面向物理仿真的可微编程

一句话结论

DiffTaichi 将 Taichi 的命令式并行 megakernel 与“两尺度”自动微分结合起来，使复杂物理模拟器可以用接近普通前向程序的代码获得高性能反向传播；但可微并不自动意味着梯度正确，碰撞、时间离散、迭代求解器和非光滑目标仍需要专门的数值设计。

论文信息卡片

标题：DiffTaichi: Differentiable Programming for Physical Simulation 作者：Yuanming Hu, Luke Anderson, Tzu-Mao Li, Qi Sun, Nathan Carr, Jonathan Ragan-Kelley, Frédo Durand 状态：2020，ICLR 2020 conference paper 资源：arXiv

研究问题与领域位置

可微物理模拟器把物理演化放进机器学习或优化的内循环：给定控制器参数、初始状态或材料参数，运行模拟得到损失，再通过梯度更新这些变量。它能够把控制优化从黑箱试错变成端到端梯度下降，尤其适合软体机器人、流体、碰撞系统和可微渲染。

论文针对的瓶颈是：现有自动微分工具通常面向张量运算，难以同时满足物理仿真的三项需求。

  • 高算术强度与融合：粒子—网格交互、数值 stencil 和边界处理需要把多个步骤融合进 megakernel；
  • 命令式并行：物理代码天然包含循环、分支、原地更新和原子累加，直接改写为函数式数组程序会降低可读性与性能；
  • 灵活索引：scatter/gather、稀疏邻接和非逐元素更新不能简单用同形状逐元素算子表达。

DiffTaichi 的定位不是一个新的物理离散方法，而是一套嵌入 Python 的可微编程语言、编译器扩展和模拟器实现方式。它希望让研究者在保留前向物理代码结构的同时自动生成反向程序，并在 CPU/GPU 上保持接近手写 CUDA 的性能。

论文主张： 通过源码变换、轻量 tape、全局张量 checkpoint 和 Taichi 的并行编译，DiffTaichi 能快速构建 10 类可微物理模拟器，并在控制优化任务中实用。

解释： 贡献的核心是“可编程性—性能—可微性”的工程折中。它把 AD 的难点从用户代码中移到编译器和少数物理数值修正中，但没有消除物理系统本身的非光滑性。

Taichi 基础与前向程序

Taichi 将计算与数据结构解耦：程序员通过 x[i,j,k] 访问张量，而底层布局由编译器根据稀疏/密集结构和访问模式优化。并行 for 是一等构造，适合把粒子或网格上的独立计算映射到 CPU/GPU 线程。

DiffTaichi 前端嵌入 Python：Python AST transformer 把程序降为 Taichi IR，再经过类型检查、IR 简化和 LLVM/CUDA 代码生成。语言本身是编译的、静态类型的、并行的和可微的，不等同于直接对 Python 解释器做 tracing。

两尺度自动微分系统

核内由源码变换生成 adjoint kernel，核间由 tape 记录调用并以逆序重放。

设计选择

如果对整个数千步模拟做一次性 source code transformation，理论上性能高，但编译时间长、灵活性差；如果对每个算子进行朴素 tracing，灵活但会破坏 megakernel 结构并保存大量中间缓冲区。

DiffTaichi 因此采用两个尺度：

  1. Local AD：对单个 Taichi kernel 做源码变换，生成反向 kernel；
  2. Global AD：用轻量 tape 记录 kernel 函数指针和标量参数，反向时逆序调用对应梯度 kernel。

全局张量本身承载前向状态，因此 tape 不需保存每个算子的中间值。它只记录“调用了哪个 kernel、传入了什么参数”，而状态历史和 adjoint tensor 的布局由用户或 Taichi 数据结构系统管理。

命令式全局数据规则

为了让原地更新的反向传播定义清晰，论文要求：

  1. 如果一个全局张量元素被写入多次，从第二次写入起必须使用 atomic add 形式的累加；
  2. 一个元素的累加完成前不能发生读取。

这些规则意味着普通的覆盖式写入不一定可微。质量—弹簧示例保存 和 的完整时间历史，而不是只保留最新值；长时间仿真的内存压力需通过 checkpointing 缓解。

Local AD 的 IR 预处理

物理 kernel 常见分支和可变局部变量。DiffTaichi 在反向变换前执行两类简化：

  • Flatten branching：将 if 转换成 select(condition, true, false)，使分支梯度可以沿同一条直线代码计算；
  • Eliminate mutable local variables：通过 store forwarding 将局部变量改写为单赋值形式，便于逆序生成 adjoint。

之后对直线 SSA 风格的 IR 执行 reverse-mode source transformation。外层并行循环结构保留；非显式并行的循环在反向时逆序遍历。带有突变局部状态的循环不直接支持，用户需改写为满足全局数据规则的形式。

原子操作与 adjoint

前向并行写入使用 atomic 操作保证线程安全；反向传播中，梯度贡献也使用 atomic add 累积到输入 adjoint tensor。这样 scatter 型物理算子可以在 GPU 上保持并行，而不必退化为串行更新。

Tape 与端到端梯度

在 ti.Tape(loss) 上下文中，程序员运行前向 kernel 和损失 kernel。每次 kernel 启动都追加到 tape，反向时从最后一次调用开始，执行相应的 gradient kernel。梯度默认针对输入全局张量求导；若待优化变量是 Python 参数，需要将其存入可微全局 tensor。

质量—弹簧例子把三个弹簧静止长度作为优化变量，目标是使末端三角形面积接近 0.2。200 次梯度下降后，长度从 优化到约 。

十类模拟器覆盖

论文用 DiffTaichi 实现：

  • 连续介质：弹性体 MPM、液体、不可压缩烟雾、浅水波；
  • 离散机械系统：质量—弹簧、刚体、台球；
  • 可微渲染与场：水面折射渲染、体渲染、静电场。

这些案例覆盖软体机器人、流体、刚体碰撞、神经网络控制器和端到端渲染优化。它们证明的是语言和 AD 系统的表达范围，不等于每种模拟器都达到了同样的物理精度或梯度质量。

梯度质量：最重要的诊断结果

时间离散会制造错误梯度

前向结果可能几乎一致，但只在离散时间步检测碰撞会把梯度方向算错。

无摩擦弹性小球撞地面时，真实关系是：降低初始高度会让最终高度升高，因此最终高度对初始高度的梯度应为负。朴素积分器只在 检测碰撞，时间网格的跳变使求得梯度为 ；加入连续 time of impact（TOI）后，碰撞可发生在任意时刻，梯度恢复为正确的负值。

解释： 这是论文最重要的 methodological warning：自动微分忠实地微分了“离散程序”，不一定微分了程序想近似的连续物理系统。要获得可用于控制的梯度，数值积分器本身必须对事件时刻敏感。

TOI 对控制优化的影响

加入连续碰撞时间后，梯度下降在三个控制任务中更稳定、损失更低。

TOI 对前向轨迹影响很小，却明显改善质量弹簧机器人和刚体机器人的控制优化。论文每个实验重复 5 次，并强调“带 TOI 优化的控制器在不带 TOI 的前向模拟器里也能正常工作”，说明 TOI 主要改善的是反向信号，而不是把前向物理模型完全换掉。

梯度失效与非光滑物理

平坦目标与局部极小

多数初始速度角度不会让白球碰到其他球，导致目标函数近似常数；有效区域又包含多个局部极小。

台球场景展示了初始化的重要性：大多数初始角度下白球根本不触发链式碰撞，蓝球与目标的最终距离保持约 0.065，梯度近似为零。局部扫描区域还存在复杂碰撞带来的多个局部极小。即使 AD 完全正确，梯度下降也可能没有可用搜索方向。

碰撞摩擦导致不连续

微小改变刚体初始旋转角，可能改变先接触地面的角点和摩擦冲量，从而造成末端位置跳变。

论文将刚体碰撞比作比 ReLU 更复杂的非光滑系统：某些点不可微，某些点甚至发生输出不连续。静电场和质量弹簧中的 项在 时还会产生数值不稳定，因为

迭代求解器的反向问题

烟雾实验只反传 10 次 Jacobi 压力投影。在更大规模设置中，若使用多重网格共轭梯度并展开几十次迭代，直接微分整个迭代过程可能因数值漂移导致不准确梯度。论文建议前向继续使用高效迭代求解器，反向通过 complex_kernel_grad 替换为手写伴随方法。

可复用思想

方法机制

  • 核内源码变换 + 核间 tape：在不牺牲 megakernel 的情况下获得端到端反传；
  • 全局张量作为 checkpoint：把状态存储和 AD 调度分离；
  • 复杂 kernel 可覆盖：对 SVD、Poisson 求解等数值敏感模块注册专用梯度；
  • 显式 flexible indexing：让 stencil、粒子—网格 scatter 和原子累加保留自然写法；
  • 分段重计算：用 级内存换取可接受反向时间。

实验设计

  • 同时报告代码长度、前向时间、反向时间和总时间，不只展示最终任务损失；
  • 为“梯度正确性”设计解析可验证的碰撞小例子；
  • 将 forward fidelity 与 gradient utility 分开评估；
  • 用带/不带 TOI 的同一控制任务做数值修正消融。

不应直接照搬

  • 把编译器生成的梯度默认视为真实连续物理梯度；
  • 在碰撞、摩擦和迭代线性求解器上直接展开 AD 而不做事件或伴随处理；
  • 用没有梯度的随机初始化直接优化长时域接触任务；
  • 只报告 forward 速度，不报告 backward、内存、JIT 和梯度误差。

局限

  1. 全局数据访问规则限制编程自由：原地写入必须转成累加，且累加完成前不能读取；现有代码移植时可能需要改变状态布局。
  2. 内存与时间权衡：完整保存时间历史会产生 空间；checkpointing 通过重计算降低内存，但增加反向时间和实现复杂度。
  3. 控制流支持边界：带可变局部变量的循环不直接支持，需要改写；复杂分支被 flatten 后，非光滑选择点仍可能产生不稳定梯度。
  4. 离散碰撞不连续：TOI 只能修正时间离散造成的一类错误，摩擦接触和多体冲量仍可能产生真正的不连续。
  5. 迭代求解器误差：展开过长的 Jacobi/CG 迭代可能产生漂移，需手写 backward。
  6. 任务优化的可达性：落地机器人会进入平坦目标或零梯度区域，优化器可能需要课程学习、随机重启或更高层规划。
  7. 硬件与软件版本：论文基准使用 GTX 1080 Ti，JIT 时间、编译器和 CUDA 版本会影响绝对速度；当前 Taichi 版本与论文时期实现可能不完全兼容。
  8. 物理准确度评测有限：论文强调开发效率和梯度用途，未对所有 10 个模拟器给出统一的解析误差或与高精度物理引擎的系统比较。

复现要点

  1. 从论文对应的开源 DiffTaichi/Taichi 代码开始，优先运行 mass_spring_simple.py 和 rigid_body_toi.py 等单脚本案例；
  2. 记录 Python、Taichi、LLVM/CUDA、GPU 型号和 JIT 时间；
  3. 先复现 diffmpm 与 smoke 的前向/反向时间，再复现控制优化，不要用单次运行比较噪声很大的毫秒差异；
  4. 检查全局数据访问是否满足 atomic add 和“累加完成前不可读”规则；
  5. 长时间模拟采用分段 checkpoint，验证内存从 降至 的趋势；
  6. 对碰撞任务分别运行 naive 与 TOI 版本，比较解析梯度、优化损失曲线和最终控制器；
  7. 对 SVD、压力投影等迭代模块使用 complex_kernel_grad，不要默认展开所有迭代步骤；
  8. 报告至少三类指标：前向结果误差、梯度有限差分误差、下游优化成功率；
  9. 复现实验时使用多次随机种子，因为论文的 TOI 优化图重复 5 次，而许多附录案例是定性展示。

开放问题

  1. 如何自动检测一个物理 kernel 的离散事件是否会让 AD 梯度偏离连续系统梯度？
  2. 能否让编译器自动选择 TOI、软接触或事件伴随，而不要求用户手写复杂 kernel？

总体评价

DiffTaichi 的长期影响不在于某个具体模拟器，而在于它把可微物理从“手工 CUDA + 手工梯度”推进为一种可编程编译系统。最值得复用的是两尺度 AD 结构和对梯度失效的诚实诊断：TOI、checkpoint、complex kernel 与初始化策略都是可微机器人研究中不可缺少的数值组件。

这篇论文也提醒后续工作区分三件事：前向仿真是否接近物理、反向梯度是否接近连续系统、梯度下降是否真的能找到任务解。DiffTaichi 在第一和第三项的多个案例中表现出色，但第二项需要针对每个非光滑物理过程单独验证。
